# Architecture and boundaries

```text
Client -> deterministic HMAC allocator -> assignment ledger
Client -> validated outcome event --------> outcome ledger
SQLite joins -> CUPED / bootstrap / SRM -> JSON report
                          ^
              CLI / FastAPI adapters
```

The service layer owns orchestration, the store layer owns SQLite transactions, and the statistics layer has no persistence dependencies. Assignment is persisted before outcome ingestion. A unique event ID and unique `(experiment_id, subject_id)` constraint enforce idempotent final-outcome ingestion. A duplicate event with an altered payload fails rather than being silently ignored.

SQLite is deliberately used for portability. Each operation opens a short-lived connection; concurrent write throughput and long-term schema migration need dedicated production engineering. No asynchronous ingestion, authentication, privacy deletion, feature flag rollout, or cross-region failover is implemented.

The architecture diagram is generated by `python scripts/generate_diagram.py`; it is a committed SVG rather than a remote image dependency.
